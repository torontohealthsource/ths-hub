"Verified" is a claim about a date, or it is not a claim at all

A code described as verified, with nothing beside it, is unfalsifiable. It cannot be wrong, because it was never attached to a moment that could have passed. That is precisely why the word is so common on coupon pages and so rarely accompanied by a timestamp: the undated version carries all of the reassurance and none of the exposure.

The useful form is narrow. A verification is a statement that a specific code produced a specific reduction on a specific cart on a specific date. Anything short of that is someone telling you a code worked at an unspecified point in the past, which is also true of codes that stopped working months ago.

What a verification should contain to be worth reading

Four components make it checkable: the code itself, the cart subtotal it was applied to, the resulting total, and the date. With all four you can tell whether the percentage is what was claimed, whether it was tested at a realistic order size, and how stale the result is. With any one missing, you are being asked to trust rather than check.

Codes end, and a dated record is how you find out quickly

No verification is permanent, because a discount code is a setting on someone else's store and can be changed without notice. A code published with no expiry date is not promising never to expire; it is reporting that no end date was advertised, which is a different statement and the only honest one available.

This is the practical argument for a dated record over a static claim. If a code stops working, a page that re-tests daily shows the change within a day, while a page that said "verified" once stays wrong indefinitely and has no mechanism that would ever notice. When you are evaluating any coupon source, the question is not whether it says the code works — it is whether anything would happen if the code stopped.
